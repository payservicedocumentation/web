# PayIN NoUI API Specification V2 INDIA

# PayIN NoUI API

## **1. Authentication**

In order to access the API, clients must authenticate using a token. The token should be included in the request header as an authorization bearer token. This token will be generated by the API provider.

**Header example**

---

Authorization: `Bearer <your_token_here>`

---

## **2. Payment Initialization by Merchant**

The payment initialization process involves the merchant initiating a payment request.

## **Request**

| **Instance** | **Method** | **URL** |
| --- | --- | --- |
| **PROD** | **POST** | https://navenpravah.in/v2/payin/client/noui |
| **SANDBOX** | **POST** | https://merchant-api.pserv-iner.in/v2/payin/client/noui |

Request parameters are being sent in a form of JSON.

**Request example**

---

```jsx
curl --location --request POST 'https://navenpravah.in/v2/payin/client/noui' \
--header 'Authorization: Bearer <your_token_here>' \
--header 'Content-Type: application/json' \
--data-raw '{
    "sender_account": "Test ID sender",
    "sender_name": "Test name sender",
    "amount": 100,
    "currency": "INR",
    "payment_method_type": "imps",  // Optional or Change to "upi" for UPI method or "upi_intent" for UPI Intent-based payments or "mqr"
    "webhook_url": "https://example.com",
    "merchant_request_id": "34535432",
    "traffic_type": "ftd", // or "std" - Optional parameter
    "campaign": "clm8wvjah774323vgcdqful7re7" // Optional
}'
```

---

### Parameter Descriptions

- **sender_account**

  The `name` or `unique_id` of the person who will send the money.

  **sender_name (Optional)**
  The full name of the person who will send the money. This field is optional and can be used to provide additional context about the sender. Maximum length: 150 characters.

- **amount**

  The `amount` of money that will be transferred by the sender.

- **currency**

  The `currency` of the transaction. Currently, only 'INR' is supported.

- **payment_method_type (Optional)**

  This parameter specifies the type of payment method. Possible values are `"imps"`, `"upi"`, `"upi_intent"`, or `"mqr"` (all in lowercase). Merchants should set this parameter based on the desired payment method:

  - **`"imps"`** – for IMPS (Immediate Payment Service).
  - **`"upi"`** – for standard UPI (Unified Payments Interface) transactions.
  - **`"upi_intent"`** – for UPI Intent-based payments, where the transaction is initiated via a UPI app (e.g., Google Pay, PhonePe).
  - **`"mqr"`** - for MQR (Merchant QR) based payments. This method allows the user to scan a static or dynamic QR code that encodes payment details.

  It is essential to specify this parameter to ensure the correct payment method is used for the transaction. For `"upi_intent"`, merchants must redirect the user to the appropriate UPI application for transaction completion.

- **webhook_url**

  The URL for receiving webhook notifications on the success or failure of the transaction.

- **merchant_request_id**

  A unique identifier of the request provided by the client.

- **traffic_type** *(optional)*: Specifies the type of traffic being processed.

  Possible values:

  `"ftd"` — for first-time deposit traffic.

  `"std"` — for secondary or recurrent traffic.

  If not provided, the system will handle the transaction with default traffic type settings.

  This parameter helps differentiate between various traffic types for better reporting and analysis of transaction flows.

- **campaign** (optional)

  A unique identifier of the campaign associated with the PayIn transaction. This parameter can be used for tracking and analytics purposes.

### Notes for Merchants:

- The `payment_method_type` must be specified to determine whether the transaction should proceed via IMPS or UPI. Make sure to select the appropriate method based on your service and user requirements.
- The `webhook_url` is crucial for receiving updates about the transaction status, so ensure that it is correctly configured to handle incoming notifications.

## **3. Upload Payment Confirmation (UTR/RECEIPT)**

This query allows the merchant to upload the confirmation document for a PayIN transaction that was previously initiated. Maximum data size 1MB.

## **Request**

| **Instance** | **Method** | **URL** |
| --- | --- | --- |
| **PROD** | **POST** | https://navenpravah.in/v2/payin/client/noui/{ps_request_id}/upload |
| **SANDBOX** | **POST** | https://merchant-api.pserv-iner.in/v2/payin/client/noui/{ps_request_id}/upload |

**Request example (Receipt)**

---

```jsx
curl --location --request POST 'https://navenpravah.in/v2/payin/client/noui/clikqi25s0001trm20q0qa5dr/upload' \
--header 'Authorization: Bearer <your_token_here>' \
--form 'file=@"/D:/files/payment_confirmation.pdf"'
```

---

**Request example (UTR)**

```jsx
curl -X POST 'https://navenpravah.in/v2/payin/client/noui/cm66grnyt0002d8pj6rj485cb/upload-utr' \
--header 'Content-Type: application/json' \
--header 'Authorization: Bearer {{AUTH_PARTNER_TOKEN}}' \
--data '{
    "utr": "9876543210"
}'
```

**Description**

When uploading a receipt for transactions in India, it is possible to attach additional information to enhance the likelihood of successful completion of the transaction. One such piece of information is the Unique Transaction Reference (UTR).

- **UTR (optional)**: A unique transaction ID for Indian payments. If the client provides a UTR, it facilitates the automatic status update of the transaction, improving the speed and accuracy of the payment process.
- **Receipt (optional)**: A receipt for PayIn transactions. If the client attaches a receipt, the request will not receive a "Reject" status but will move to a "Review" status for further verification.

## **4. Request Status**

To retrieve the current status of a payment request, clients should make a GET request to the following endpoint.

## **Request**

| **Instance** | **Method** | **URL** |
| --- | --- | --- |
| **PROD** | **GET** | https://navenpravah.in/payin/client/noui/{ps_request_id} |
| **SANDBOX** | **GET** | https://merchant-api.pserv-iner.in/payin/client/noui/{ps_request_id} |

The `{ps_request_id}` parameter should be replaced with the unique identifier of the payment request issued by Payment System.

**Request example**

---

```jsx
curl --location --request GET 'https://navenpravah.in/payin/client/noui/clgggiss10003dvm2qnd01n5e' \
--header 'Authorization: Bearer <your_token_here>'
```

---

## **Response**

| **Status** | **Response** |
| --- | --- |
| 200 | `{ "id": "clgggiss10003dvm2qnd01n5e", "status": "pending", "amount": 2000, "currency": "INR", "receivedAmount": 2000, "isChargeback": false, "merchantRequestId": "34535432" }` |
| 401 | `{ "error": { "code": "invalid_token", "message": "The provided token is invalid or has expired." } }` |
| 401 | `{ "error": { "code": "missing_required_field", "message": "One or more required fields are missing in the request." } }` |
| 404 | `{ "error": { "code": "invalid_payin", "message": "Payin not found." } }` |
| 500 | `{ "error": { "code": "server_error", "message": "Get support from api developer." } }` |

Response parameters:

| **Params** | **Values** |
| --- | --- |
| id | string |
| status | string |
| amount | number |
| currency | string |
| receivedAmount | number |
| merchantRequestId | string |

**status**

The current `status` of the payment request.

| Value | Description |
| --- | --- |
| `pending` | Processing of transaction has not started yet |
| `completed` | Payment operation complete |
| `rejected` | Transaction is rejected due to technical reasons (wrong card number or bank) |
| `successed_by_partner` | Transaction is complete and sent to Merchant server successfully |
| `rejected_by_partner` | Transaction is rejected and sent to Merchant server successfully |

**amount** — The `amount` of money that was expected to be transferred by the sender.

**currency** — The ISO 4217 `currency` code.

**receivedAmount** — The amount of money actually transferred.

## **5. Webhook notifications**

Webhooks are used to inform the client about the change in status of their payout requests. When a payout status changes, the system sends a webhook notification to the client's specified `webhook_url`.

## **Webhook Payload**

| Field | Description |
| --- | --- |
| `merchant_request_id` | Unique identifier of the request from the client |
| `ps_request_id` | The unique identifier of the request inside Payment System |
| `status` | The current status of the payment request (see status description above) |
| `amount` | The amount of money that was expected to be transferred by the sender |
| `receivedAmount` | The amount of money actually transferred |
| `currency` | The ISO 4217 currency code |
| `isChargeback` | Boolean — chargeback flag |

**Data example**

---

```jsx
{
    "merchant_request_id": "123456",
    "ps_request_id": "clcszbdt937269ouwdl27c8nq",
    "status": "completed",
    "amount": 6000,
    "receivedAmount": 6000,
    "isChargeback": false,
    "currency": "INR"
}
```

---

**Webhook Signature**

To verify the authenticity of the webhook notification, the client should check the signature in the `signatureV2` header. The signature is generated using the request body and salt.

Example of verifying the signature in Node.js:

```jsx
const salt = '<your-salt>';
const signature = request.headers.signatureV2;
const bodyString = JSON.stringify(request.body);
const isReal = bcrypt.compareSync(bodyString, salt + signature);
```

## **9. Digital Signature (Optional)**

**1. Generate private key:**
```bash
openssl genpkey -algorithm RSA -out private_key.pem
```

**2. Generate public key:**
```bash
openssl rsa -pubout -in private_key.pem -out public_key.pem
```

**3. Sign request body (NodeJS example):**

```js
import * as crypto from 'crypto';
import axios from 'axios';

const privateKey = <PRIVATE KEY>

const body = {
  field1: "1",
  field2:  2
};

const jsonBody = JSON.stringify(body);
const sign = crypto.createSign('SHA512');

sign.update(jsonBody);
sign.end();

const signature = sign.sign(privateKey, 'hex');
const url = <URL_FOR_REQUEST>;

const requestConfig = {
  headers: {
    'Content-Type': 'application/json',
    'DigitalSignature': signature
  }
}

await axios.post(url, body, requestConfig);
```

**4. Check signature (NodeJS example):**

```js
import * as crypto from 'crypto';
const publicKey = <PUBLIC KEY>

const body = {
  field1: "1",
  field2:  2
};

const jsonBody = JSON.stringify(body);
const verify = crypto.createVerify('SHA512');

verify.update(jsonBody);
verify.end();

const isValidSignature = verify.verify(publicKey, signature, 'hex');
console.log('Is signature valid:', isValidSignature);
```

## **11. Payment Instructions for Customers in India**

### Payment via UPI (Unified Payments Interface)

**Mandatory fields for the UPI payment widget:**

1. **Payment Amount (Amount)** – Enter the amount to be paid (e.g., 500 INR). This is handled on the client's website.
2. **Payment Method Selection** – Select UPI as the payment method.
3. **QR Code / UPI ID** – Copy details such as the UPI ID or use the QR code for scanning.
4. **Payment Session Timer** – Displays the remaining time to complete the payment (usually 4 minutes).
5. **Field for UTR Number** – Mandatory field to enter the UTR (Unique Transaction Reference) in case of successful or unsuccessful payment.
6. **Field to Attach Payment Receipt** – Optional but crucial for speeding up payment processing. Attach a screenshot of the payment receipt in case of a failed transaction or session timeout.

**Payment Process:**

1. Select UPI as the payment method.
2. Click "Go to payment."
3. Copy the provided details (UPI ID or QR code). Keep an eye on the timer to complete the transaction before the session expires.
4. Open your banking app.
5. In the "Send Money" section, choose UPI.
6. Paste the UPI ID and enter the payment amount.
7. Complete the transfer, copy the UTR, and take a screenshot of the receipt.
8. Return to the payment page, confirm the payment by selecting "I made the transfer (in one payment)" and click the active "Continue" button.
9. If the payment is successful and matches the request, the user will be redirected to the success page. No further details are required.
10. In case of failure at step 8, the user will have the opportunity to input additional data, leading to the "Transfer Review" page.
11. On the "Transfer Review" page, enter the UTR number (step 7). The UTR field is mandatory at this step to help us process the client's transaction faster. Skipping this field is not allowed.
12. Optionally, attach the payment receipt screenshot and click "Send." This step is optional but crucial for faster information processing.
13. After clicking "Send," the user sends the data for further processing. If everything is correct, they will receive a success page. If there are further issues, the user will get one last chance to upload the receipt, which at this step becomes a **mandatory** field.

**If the session time expires:**

1. The user will automatically be redirected to the failure page.
2. Attach the payment receipt; in this case, a screenshot will be the optimal solution for the user.
3. Click "Send" to confirm the payment.

### Payment via IMPS (Immediate Payment Service)

**Mandatory fields for the IMPS payment widget:**

1. **Payment Amount (Amount)** – Enter the amount (e.g., 500 INR).
2. **Payment Method Selection** – Select IMPS as the payment method.
3. **Beneficiary Details** – Copy the recipient's account number and IFSC code.
4. **Payment Session Timer** – Displays the remaining time to complete the payment (usually 6 minutes).
5. **Field for UTR Number** – Mandatory field to enter the UTR (Unique Transaction Reference) in case of successful or unsuccessful payment.
6. **Field to Attach Payment Receipt** – Optional but crucial for speeding up payment processing. Attach a screenshot of the payment receipt in case of a failed transaction or session timeout.

**Payment Process:**

1. Select IMPS as the payment method.
2. Click "Go to payment."
3. Copy the recipient's details (account number and IFSC code). Keep an eye on the timer to complete the transaction before the session expires.
4. Open your banking app.
5. In the "Send Money" section, choose IMPS.
6. Enter the recipient's details and the payment amount.
7. Complete the transfer, copy the UTR, and take a screenshot of the receipt.
8. Return to the payment page and paste the UTR number.
9. Attach the payment receipt screenshot and click "Send."

**If the session time expires or the payment is unsuccessful:**

1. Go to the retry page.
2. Enter the UTR number.
3. Attach the payment receipt.
4. Click "Send" to confirm the payment.

---

> **Important:** In case of session timeout or unsuccessful payment, the customer must provide the UTR number and attach a payment receipt screenshot for transaction re-verification.
