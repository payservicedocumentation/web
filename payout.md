# PayOUT API Specification V2 INDIA

# PayOUT API

## **1. Authentication**

In order to access the API, clients must authenticate using a token. The token should be included in the request header as an authorization bearer token. This token will be generated by the API provider.

**Header example**

---

Authorization: `Bearer <your_token_here>`

---

## **2. Create Payment Request by Merchant**

The payment initialization process involves the merchant initiating a payment request.

## **Request**

| **Instance** | **Method** | **URL** |
| --- | --- | --- |
| **PROD** | **POST** | https://navenpravah.in/v2/payout/client |
| **SANDBOX** | **POST** | https://merchant-api.pserv-iner.in/v2/payout/client |

Request parameters are being sent in a form of JSON.

**Request example**

---

```jsx
curl --location --request POST 'https://navenpravah.in/v2/payout/client' \
--header 'Authorization: Bearer <your_token_here>' \
--header 'Content-Type: application/json' \
--data-raw '{
    "merchant_request_id": "0000",
    "request_date": "2020-06-29 21:10:36",
    "payout_amount": 6000,
    "payout_currency": "INR",
    "recipient_bank": "Ziraat Bank",
    "recipient_card": "jerom123@kkotak",
    "recipient_name": "Test client",
    "webhook_url": "https://example.com",
    "campaign": "clm8wvjah774323vgcdqful7re7",
    "ifsc": "FFFFF0000000"
}'
```

---

### Parameter Descriptions

- **merchant_request_id**

  A unique identifier of the request provided by the merchant. This ID is used to track and reference the specific payout transaction.

- **request_date**

  The date and time of the payout request in `yyyy-mm-dd hh:mm:ss` format. It indicates when the payout transaction was initiated.

- **payout_amount**

  The amount of money to be paid out in the specified currency. This is the total sum that the recipient will receive.

- **payout_currency**

  The currency of the transaction. Currently, only Indian Rupees (`INR`) is supported.

- **recipient_bank**

  The name of the recipient's bank. This is necessary to identify the financial institution where the payout will be directed.

- **recipient_card**

  This field should contain either the **UPI ID** or the **bank account number**, depending on the payment method used:

  - **For UPI payments**: The field should contain the valid UPI ID of the recipient (e.g., `"jerom123@kkotak"`). Ensure the VPA suffix/handle is correct and supported, otherwise the request will fail with an `invalid_upi` error.
  - **For IMPS payments**: The field should contain the recipient's bank account number (e.g., `"123456789012"`).

  **Example for UPI**: `"recipient_card": "jerom123@kkotak"`

  **Example for IMPS**: `"recipient_card": "123456789012"`

- **recipient_name**

  The full name of the recipient. This is required for identification and verification purposes.

- **webhook_url**

  The URL where notifications about the success or failure of the transaction will be sent. This allows the merchant to receive updates on the status of the payout.

- **campaign** (optional)

  An optional unique identifier for the campaign associated with this payout transaction. This can be used for tracking and analysis purposes.

- **ifsc** (string)

  The Indian Financial System Code (IFSC) is required only for the IMPS payment method. This alphanumeric code facilitates electronic funds transfer in India and is used to identify the bank and branch.

  - This field is **mandatory** when using the **IMPS** payment method. Format: `"FFFFF0000000"` (letters + numbers).
  - If using the **UPI** payment method, the `ifsc` field is **not required**.

## **Response**

| **Status** | **Response** |
| --- | --- |
| 201 | `{ "ps_request_id": "clcszbdt937269ouwdl27c8nq" }` — `ps_request_id` (string): The ID of the payment inside Payment System |
| 400 | `{ "error": { "code": "invalid_upi", "message": "Invalid UPI ID format or unsupported VPA suffix" }, "http_code": 400 }` — Triggered when a non-existent or unsupported UPI handle/suffix is provided in `recipient_card`. |
| 404 | `{ "error": { "code": "invalid_field_value", "message": "One or more field values in the request are invalid or in the wrong format." } }` |
| 502 | `{ "data": { "http_code": 502, "type": "api: create withdraw", "msg": "success", "response": null } }` — **Critical Payout Failure**. Triggered when the upstream provider fails to initialize the withdrawal. This is a final rejection on the payment system side; the payout will **not** be created, and the merchant can safely reject the order on their side. |
| 500 | `{ "error": { "code": "server_error", "message": "Get support from api developer." } }` |

## **3. Get Payout Status** by ps_request_id or by merchant_request_id

Retrieves the status of a specific payout request using the provided `ps_request_id` or `merchant_request_id`.

## **Request by ps_request_id**

| **Instance** | **Method** | **URL** |
| --- | --- | --- |
| **PROD** | **GET** | https://navenpravah.in/v2/payout/client/{ps_request_id} |
| **SANDBOX** | **GET** | https://merchant-api.pserv-iner.in/v2/payout/client/{ps_request_id} |

## **Request by merchant_request_id**

| **Instance** | **Method** | **URL** |
| --- | --- | --- |
| **PROD** | **GET** | https://navenpravah.in/v2/payout/client/merchant-request/{merchant_request_id} |
| **SANDBOX** | **GET** | https://merchant-api.pserv-iner.in/v2/payout/client/merchant-request/{merchant_request_id} |

**Request example**

---

```jsx
curl --location --request GET 'https://navenpravah.in/v2/payout/client/clcszbdt937269ouwdl27c8nq' \
--header 'Authorization: Bearer <your_token_here>'
```

---

## **Response**

| **Status** | **Response** |
| --- | --- |
| 200 | `{ "ps_request_id": "clcszbdt937269ouwdl27c8nq", "status": "completed", "payout_amount": 6000, "payout_currency": "INR", "request_date": "2020-06-29 21:10:36", "merchant_request_id": "123456", "payout_receipts": ["https://navenpravah.in/images/example.jpg"] }` |
| 404 | `{ "error": { "code": "payout_request_not_found", "message": "The requested payout ID was not found in the system." } }` |
| 500 | `{ "error": { "code": "server_error", "message": "Get support from api developer." } }` |

Response parameters:

| **Params** | **Values** |
| --- | --- |
| ps_request_id | string |
| status | string |
| payout_amount | number |
| payout_currency | string |
| request_date | string |
| merchant_request_id | string |
| fee | number |
| payout_receipts | string[] |

**status**

The `status` of payout transaction.

| Value | Description |
| --- | --- |
| `pending` | Processing of transaction has not started yet |
| `processing` | Transaction is under processing |
| `completed` | Payment operation complete |
| `rejected` | Transaction is rejected due to technical reasons (wrong card number or bank) |
| `successed_by_partner` | Transaction is complete and sent to Merchant server successfully |
| `rejected_by_partner` | Transaction is rejected and sent to Merchant server successfully |

**payout_amount** — The `amount` of money to be paid out.

**payout_currency** — The ISO 4217 `currency` code.

**request_date** — Date in `yyyy-mm-dd hh:mm:ss` format.

**merchant_request_id** — Unique identifier of the request provided by Merchant.

**payout_receipts** — Array of strings. Receipt links of current payout.

## **4. Webhook notifications**

Webhooks are used to inform the client about the change in status of their payout requests. When a payout status changes, the system sends a webhook notification to the client's specified `webhook_url`.

## **Webhook Payload**

| Field | Description |
| --- | --- |
| `ps_request_id` | The unique identifier of the request inside Payment System |
| `status` | The status of payout transaction (see status description above) |
| `payout_amount` | The amount of money to be paid out |
| `payout_currency` | The ISO 4217 currency code |
| `merchant_request_id` | Unique identifier of the request from the merchant |
| `fee` | Transaction fee |
| `payout_receipts` | Array of strings — receipt links of current payout |

**Data example**

---

```jsx
{
    "ps_request_id": "clcszbdt937269ouwdl27c8nq",
    "status": "completed",
    "payout_amount": 6000,
    "payout_currency": "INR",
    "merchant_request_id": "0000",
    "fee": 100,
    "payout_receipts": [
        "https://navenpravah.in/files/example.pdf",
        "https://navenpravah.in/images/example.png"
    ]
}
```

---

**Webhook Signature**

To verify the authenticity of the webhook notification, the client should check the signature in the `signatureV2` header. The signature is generated using the request body and salt.

Example of verifying the signature in Node.js:

```jsx
const salt = '<your-salt>';
const signature = request.headers.signatureV2;
const bodyString = JSON.stringify(request.body);
const isReal = bcrypt.compareSync(bodyString, salt + signature);
```

## **6. Digital Signature (Optional)**

**1. Generate private key:**
```bash
openssl genpkey -algorithm RSA -out private_key.pem
```

**2. Generate public key:**
```bash
openssl rsa -pubout -in private_key.pem -out public_key.pem
```

**3. Sign request body (NodeJS example):**

```js
import * as crypto from 'crypto';
import axios from 'axios';

const privateKey = <PRIVATE KEY>

const body = {
  field1: "1",
  field2:  2
};

const jsonBody = JSON.stringify(body);
const sign = crypto.createSign('SHA512');

sign.update(jsonBody);
sign.end();

const signature = sign.sign(privateKey, 'hex');
const url = <URL_FOR_REQUEST>;

const requestConfig = {
  headers: {
    'Content-Type': 'application/json',
    'DigitalSignature': signature
  }
}

await axios.post(url, body, requestConfig);
```

**4. Check signature (NodeJS example):**

```js
import * as crypto from 'crypto';
const publicKey = <PUBLIC KEY>

const body = {
  field1: "1",
  field2:  2
};

const jsonBody = JSON.stringify(body);
const verify = crypto.createVerify('SHA512');

verify.update(jsonBody);
verify.end();

const isValidSignature = verify.verify(publicKey, signature, 'hex');
console.log('Is signature valid:', isValidSignature);
```

## **7. Server Health Check**

### Endpoint

| **Method** | **URL** |
| --- | --- |
| GET | `https://navenpravah.in/api/status/check` |

### Response

**If the server is running correctly and the gateway is accessible:**

```json
{"status": true}
```

**If the server is not running or the gateway is inaccessible:**

```json
{"status": false}
```

This endpoint allows clients to verify the operational status of the server and the gateway.
